# SemSearch — поиск по компьютеру по смыслу и по имени

Локальный поиск на EmbeddingGemma 2: документы, код, фото, видео и аудио ищутся обычной фразой
(«договор про крышу», «кот на балконе», «где парсил JSON с ретраями»), а имена файлов — по всем
дискам мгновенно, как в Everything. Ничего не уходит в интернет.

## Установка

1. Скачайте `SemSearch-Setup-<версия>.exe` и запустите его. Программа ставится для текущего пользователя
   (по умолчанию в `%LOCALAPPDATA%\Programs\SemSearch`), права администратора не нужны.
2. Windows спросит разрешение только на Visual C++ (если его нет) и на быстрый поиск по имени (задача Планировщика
   читает MFT; от неё можно отказаться — имена тогда ищутся обычным обходом, медленнее).
3. Модель (~1,5 ГБ) и PyTorch (с CUDA, если есть видеокарта NVIDIA, иначе для процессора) скачиваются во время
   установки, нужен интернет. Оборвалась сеть — «Повторить».
4. Файл не подписан, поэтому SmartScreen может предупредить: «Подробнее» → «Выполнить в любом случае».
5. Новая версия ставится поверх тем же установщиком: настройки, индекс и модель сохраняются.
6. Удаляется через «Приложения» / «Установка и удаление программ»; при удалении можно стереть и настройки, индекс и модель.

## Требования

- Windows 10 версии 1709 или новее, 64-бит. Программа работает только в Windows.
- Видеокарта NVIDIA RTX 20xx или новее — по желанию: без неё (или со старой картой) модель считает на процессоре, медленнее.
- WebView2 Runtime — в Windows 11 уже есть, в Windows 10 обычно ставится вместе с Edge (нет — установщик предложит его поставить).
- Около 7 ГБ на диске с видеокартой NVIDIA, около 3,5 ГБ без неё: окружение Python, модель (~1,5 ГБ) и индекс.

## Запуск из исходников

Нужны Python 3.11 или новее и, для `SemSearch.exe` и движка имён, Rust с Visual Studio Build Tools (см. «Разработка»).
Модель (~1,5 ГБ) скачается при первом запуске.

1. `setup.bat` — окружение Python: PyTorch с CUDA, если есть драйвер NVIDIA, иначе сборка для процессора.
2. `build.cmd` — собирает `SemSearch.exe` и `bin\semsearch-engine.exe`.
3. `SemSearch.exe` — окно поиска; программа живёт в трее. Без сборки можно запустить `start.bat` —
   поиск откроется в браузере, а имена будут искаться встроенным обходом (медленнее).
4. По желанию — `engine\install-task.cmd`, чтобы имена индексировались через MFT (см. «Движок имён»).

## Управление

- **Ctrl+Alt+S** — показать/спрятать окно из любой программы, **Esc** — спрятать.
- Enter — открыть файл, Ctrl+Enter — показать в папке, ↑/↓ — выбор, Ctrl+1…7 — вкладки,
  Ctrl+F — найти похожие фото/кадры, Ctrl+Shift+C — копировать путь,
  картинку можно перетащить в окно или вставить через Ctrl+V.
- Язык (русский, английский или как в Windows), автозапуск с Windows, тема, папки, диски, исключения, паузы — в «Настройках»
  (кнопка внизу окна или меню в трее).
- Пока модель загружается, окно показывает экран запуска с шагами; при первом запуске на нём видно, как скачивается модель.
  Поиск по имени работает сразу — кнопка «Искать по имени» на этом экране.

## Из чего состоит

| Часть | Что делает |
|---|---|
| `SemSearch.exe` (Rust, Tauri; исходники `shell/`) | Окна без рамки, трей, горячая клавиша, автозапуск. Запускает и при сбое перезапускает backend. |
| `server.py` → `app.py` (Python) | Модель EmbeddingGemma 2 (на видеокарте, если она подходит), индекс содержимого, API для интерфейса. |
| `ui/` | Интерфейс 1:1 по макету «SemSearch Desktop» (исходники макета — `design/`). Значки типов файлов — в `ui/filetypes/` (набор `@pierre/trees`, Apache-2.0, и свои; лицензия и описание там же). |
| Движок имён (Rust; исходники `engine/`) | Индекс имён всех файлов на дисках: MFT + журнал USN или обход папок. Отдаёт поиск по имени за миллисекунды и поток изменений файлов. |

Контракты между частями — `docs/API.md`.

## Где хранятся данные

`%LOCALAPPDATA%\SemSearch` — настройки (`config.json`), индексы, превью, журналы и модель (`models\`, ~1,5 ГБ).
Папка программы во время работы только читается, поэтому её можно положить куда угодно, в том числе в `Program Files`.

- Другая папка для данных — переменная окружения `SEMSEARCH_DATA_DIR` (абсолютный путь). Задайте её как постоянную
  переменную пользователя — тогда её увидит и движок, запущенный задачей Планировщика.
- Если рядом с программой остались `data\` и `config.json` от старой версии, при первом запуске они переносятся сюда.
- Модель, скачанная прежними версиями в общий кэш Hugging Face (`%USERPROFILE%\.cache\huggingface\hub`),
  при первом запуске тоже переносится сюда — заново её качать не придётся. Свой кэш (`HF_HUB_CACHE`) SemSearch не трогает.

## Движок имён и права администратора

Чтобы читать MFT, движку нужны права администратора. Для этого есть задача Планировщика «SemSearch Engine»:
она стартует при входе в Windows без запроса UAC. Файл движка копируется в `%ProgramFiles%\SemSearch\`
(туда без прав администратора не записать — подменить его нельзя), журнал — `%ProgramFiles%\SemSearch\logs\engine.log`.
Из папки данных движок читает только список дисков (`config.json`).

- Установить или обновить после пересборки: `engine\install-task.cmd` (спросит UAC; нужна учётная запись администратора).
- Удалить задачу и копию в Program Files: `engine\uninstall-task.cmd`.
- Без задачи backend запускает `bin\semsearch-engine.exe` сам, без прав: обход диска + ReadDirectoryChangesW
  (индекс строится дольше, всё остальное так же). Так же, обходом, индексируются диски не NTFS (exFAT, FAT32, ReFS).

## Индексация и игры

- По смыслу индексируется папка пользователя и известные папки вне неё (например, «Документы», перенесённые
  на другой диск), кроме AppData, папок с точкой и node_modules. Файлы OneDrive, которые есть на диске, индексируются,
  а файлы «только в облаке» не скачиваются (их имена в поиске по имени есть).
  Сборки и зависимости узнаются по файлам проекта рядом, а не по одному имени папки: `bin`/`obj` рядом
  с `.csproj`, `Library` в проекте Unity, `Saved`/`Intermediate` рядом с `.uproject`, папка с `pyvenv.cfg`
  и т. п. — обычная папка «Library» с книгами в поиск попадает. Порядок: документы → код → фото → аудио → видео.
- По имени — все несъёмные диски; список меняется в «Настройках».
- Чужой код (настройка «Чужой код и библиотеки»): git-подмодули, скачанные архивы исходников (`*-main`,
  `*-master`, `*-1.2.3`), то, что `.gitignore` проекта считает не исходниками, и сгенерированные файлы
  по умолчанию не индексируются; клоны чужих репозиториев без ваших коммитов и файлы с шапкой библиотеки
  индексируются в последнюю очередь. Касается только кода и `.md`/`.rst`. Точные копии файлов считаются
  один раз — в выдаче «ещё N копий».
- Новые, изменённые, переименованные и удалённые файлы подхватываются через журнал изменений за секунды
  (файл берётся в работу, когда в него 3 секунды ничего не пишут). Раз в 6 часов — страховочный полный обход.
- Нагрузка на видеокарту подстраивается (`throttle.py`): работа режется на кусочки по 1–5 мс, чтобы кадры
  игр и рабочего стола проходили между ними. Пока вы за компьютером — мягкий режим, при тяжёлой игре в окне —
  сильное ограничение, когда вас нет — полная скорость (но не на ноутбуке от батареи и не в режиме экономии заряда).
  Полноэкранные игры и фильмы ставят индексацию на паузу. Порции подстраиваются под видеокарту: на медленной
  они меньше, на карте с 2–4 ГБ памяти — по свободной видеопамяти; если её не хватает даже на модель, считает процессор.
- HDD, флешки и сетевые диски читаются в меньшее число потоков. Внешний диск можно «Безопасно извлечь» — SemSearch
  отпускает его сам, а после подключения снова подхватывает. Индекс содержимого с отключённого диска не стирается —
  после подключения его не нужно считать заново.
  Текстовая часть модели идёт CUDA-графами, по графу на слой (`cudagraphs.py`): такой кусочек подаётся видеокарте
  одним вызовом, а не ~50 мелкими, и за то же время успевает сделать в 1,5–2,5 раза больше работы.
- Если torch не умеет работать с вашей видеокартой (сборка с CUDA 12.8 поддерживает RTX 20xx и новее, а не GTX 10xx)
  или модели не хватает видеопамяти, она автоматически считает на процессоре — причина записана в `semsearch.log`.

## Если что-то не так

Журналы лежат в `%LOCALAPPDATA%\SemSearch`: `semsearch.log` (backend), `shell.log` (окно и трей), `engine.log`
(движок без задачи). Журнал движка из задачи — `%ProgramFiles%\SemSearch\logs\engine.log`. В «Настройках» есть
список файлов, которые не удалось прочитать, и кнопка «Собрать индекс заново».

- Порт 8765 занят другой программой (например, AnkiConnect) — SemSearch сам займёт свободный порт рядом.
  Свой порт можно задать в `config.json` (`"port"`).
- В польской, чешской, венгерской и некоторых других раскладках Ctrl+Alt+S — это AltGr+S, которым набирают буквы.
  Если клавиша мешает, смените её в «Настройках». Если сочетание занято другой программой, «Настройки» об этом скажут.
- Нет WebView2 Runtime — SemSearch скажет об этом при запуске и откроет страницу загрузки.
- Сервер поиска не запускается с кодом 0xC0000135 — не хватает Microsoft Visual C++ Redistributable (x64), он нужен PyTorch.
- Драйвер NVIDIA слишком старый для CUDA 12.8 — модель считает на процессоре, в `semsearch.log` написано, что драйвер
  стоит обновить.

## Разработка

- `setup.bat` — окружение Python; версии зафиксированы в `requirements-torch.txt` (torch, torchvision) и `requirements.txt`.
- `build.cmd` — release-сборка движка (`engine\`) и оболочки (`shell\`); кладёт `bin\semsearch-engine.exe` и
  `SemSearch.exe` в корень. Нужны Rust (rustup; минимальная версия — `rust-version` в `Cargo.toml`) и Visual Studio
  Build Tools с компонентом «Разработка классических приложений на C++» (MSVC и Windows SDK). Движок и оболочка
  собираются со статическим CRT, поэтому ни `SemSearch.exe`, ни движку VC++ Redistributable не нужен.
- `installer\` и `build-installer.cmd` — установщик `dist\SemSearch-Setup-<версия>.exe`; что и как он делает,
  какие файлы кладёт (`installer\payload.txt`) — в `docs/INSTALLER.md`. `tools\fetch_model.py` — шаг установщика,
  который скачивает модель; вручную запускается так же: `.venv\Scripts\python.exe tools\fetch_model.py`.
- Подпись установщика, `SemSearch.exe` и движка (необязательна; без неё сборка идёт без подписи) — переменная
  `SEMSEARCH_SIGN` с аргументами signtool, выбирающими сертификат, одним из трёх способов:
  - файл: `set SEMSEARCH_SIGN=/f C:\keys\semsearch.pfx /p <пароль>`;
  - хранилище Windows или токен: `set SEMSEARCH_SIGN=/sha1 <отпечаток>`;
  - Azure Trusted Signing: `set SEMSEARCH_SIGN=/dlib <…\Azure.CodeSigning.Dlib.dll> /dmdf <…\metadata.json>`.

  Ещё: `SEMSEARCH_SIGNTOOL` (путь к signtool.exe, по умолчанию — из Windows Kits 10), `SEMSEARCH_SIGN_TS` (сервер
  меток времени, по умолчанию DigiCert), `SEMSEARCH_SIGN_TEST=1` (самоподписанный сертификат для проверки сборки).
- `mock_api.py` — сервер с данными из макета для вёрстки интерфейса (порт 8799). Экран запуска: `/dev/scenario/boot`,
  `firstrun`, `cpu`, `booterror`, `bootnet`, `hold-download`, `hold-model`; язык: `/dev/lang/<system|ru|en>`.
- `tools\make_filetype_icons.py` — значки типов файлов (`ui\filetypes\`, там же лицензия и описание); запускать нужно,
  только когда меняются сами значки или список расширений.
- `tools\frameprobe` (Rust) и `tools\gpu_bench.py` — замер плавности кадров под нагрузкой индексации.
- Переменные окружения (`SEMSEARCH_DATA_DIR`, `SEMSEARCH_PORT`, `SEMSEARCH_ROOT`, `SEMSEARCH_DEV_URL`,
  `SEMSEARCH_NO_BACKEND`) и контракты между частями — в `docs/API.md`.
