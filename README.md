# SemSearch — поиск по компьютеру по смыслу и по имени

Локальный поиск на EmbeddingGemma 2: документы, код, фото, видео и аудио ищутся обычной фразой
(«договор про крышу», «кот на балконе», «где парсил JSON с ретраями»), а имена файлов — по всему
диску C: мгновенно, как в Everything. Ничего не уходит в интернет.

## Запуск

- `SemSearch.exe` (или `start.bat`) — окно поиска; программа живёт в трее.
- **Ctrl+Alt+S** — показать/спрятать окно из любой программы, **Esc** — спрятать.
- Enter — открыть файл, Ctrl+Enter — показать в папке, ↑/↓ — выбор, Ctrl+1…7 — вкладки,
  Ctrl+F — найти похожие фото/кадры, Ctrl+Shift+C — копировать путь,
  картинку можно перетащить в окно или вставить через Ctrl+V.
- Автозапуск с Windows, тема, папки, диски, исключения, паузы — в «Настройках» (кнопка внизу окна или меню в трее).

## Из чего состоит

| Часть | Что делает |
|---|---|
| `SemSearch.exe` (Rust, Tauri; исходники `shell/`) | Окна без рамки, трей, горячая клавиша, автозапуск. Запускает и при сбое перезапускает backend. |
| `server.py` → `app.py` (Python) | Модель EmbeddingGemma 2 на видеокарте, индекс содержимого (`data/index.db`), API для интерфейса. |
| `ui/` | Интерфейс 1:1 по макету «SemSearch Desktop» (исходники макета — `design/`). |
| Движок имён (Rust; исходники `engine/`) | Индекс имён всех файлов диска: MFT + журнал USN. Отдаёт поиск по имени за миллисекунды и поток изменений файлов. |

Контракты между частями — `docs/API.md`.

## Движок имён и права администратора

Чтобы читать MFT, движку нужны права администратора. Он установлен задачей Планировщика
«SemSearch Engine»: стартует при входе в Windows без запроса UAC, сам файл лежит в
`C:\Program Files\SemSearch\` (туда без прав администратора не записать — подменить его нельзя),
журнал — `C:\Program Files\SemSearch\logs\engine.log`. Из папки проекта он читает только список
дисков из `config.json`.

- Переустановить после пересборки движка: `engine\install-task.ps1` (спросит UAC).
- Удалить задачу и копию в Program Files: `engine\uninstall-task.ps1`.
- Без задачи backend запускает `bin\semsearch-engine.exe` сам, без прав: обход диска
  + ReadDirectoryChangesW (индекс строится дольше, всё остальное так же).

## Индексация и игры

- По смыслу индексируется папка пользователя (кроме AppData, папок с точкой, node_modules, venv, bin/obj/build…),
  облачные файлы OneDrive не скачиваются. Порядок: документы → код → фото → аудио → видео.
- Новые, изменённые, переименованные и удалённые файлы подхватываются через журнал изменений за секунды
  (файл берётся в работу, когда в него 3 секунды ничего не пишут). Раз в 6 часов — страховочный полный обход.
- Нагрузка на видеокарту подстраивается (`throttle.py`): работа режется на кусочки по 1–5 мс, чтобы кадры
  игр и рабочего стола проходили между ними. Пока вы за компьютером — мягкий режим, при тяжёлой игре в окне —
  сильное ограничение, когда вас нет — полная скорость. Полноэкранные игры и фильмы ставят индексацию на паузу.

## Если что-то не так

Журналы: `data\semsearch.log` (backend), `data\shell.log` (окно и трей),
`C:\Program Files\SemSearch\logs\engine.log` (движок имён). В «Настройках» есть список файлов,
которые не удалось прочитать, и кнопка «Собрать индекс заново».

## Разработка

- `setup.bat` — окружение Python (PyTorch CUDA и зависимости).
- Rust-части: `cd shell && cargo build --release` → `SemSearch.exe`; `cd engine && cargo build --release` → `bin\`.
- `mock_api.py` — сервер с данными из макета для вёрстки интерфейса (порт 8799).
- `tools\frameprobe.exe` и `tools\gpu_bench.py` — замер плавности кадров под нагрузкой индексации.
